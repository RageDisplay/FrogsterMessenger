# Как протестировать Frogster самому

Пошагово, от запуска до проверки шифрования. Всё копируется как есть.

---

## Часть 0. Что понадобится

- **Docker Desktop** — запущен
- **Телефон на Android**, в той же Wi-Fi сети, что и компьютер
- Компьютер и телефон **не через VPN** — иначе они друг друга не увидят

Проверить, что Docker жив:

```powershell
docker ps
```

Если ошибка — запустите Docker Desktop и подождите, пока значок перестанет крутиться.

---

## Часть 1. Узнать IP компьютера

Телефон будет подключаться к вашему ПК по сети, поэтому нужен его адрес.

```powershell
ipconfig
```

Найдите блок вашего **Wi-Fi адаптера** и строку **IPv4-адрес**. Будет вида
`192.168.50.238`.

> Игнорируйте адреса `192.168.200.1`, `192.168.250.1` и подобные — это
> виртуальные адаптеры VirtualBox/VMware, телефон через них не пройдёт.

**Запишите этот адрес.** Дальше он нужен трижды. В инструкции он обозначен
как `ВАШ_IP`.

## Часть 2. Поднять инфраструктуру

Откройте PowerShell в папке проекта.

```powershell
cd d:\VectrixSecurity\Frogster
docker compose -f deploy/docker-compose.yml up -d
```

Проверить, что оба контейнера поднялись:

```powershell
docker compose -f deploy/docker-compose.yml ps
```

Должно быть **два** контейнера со статусом `healthy`:

```
postgres   Up ... (healthy)
redis      Up ... (healthy)
```

Если `redis` не запустился с ошибкой про порт — см. раздел «Если что-то пошло не так».

Ожидаемый конец вывода:

## Часть 4. Запустить серверы

Нужны **два отдельных окна PowerShell** — каждый сервер занимает своё окно и
не отдаёт управление обратно.

### Окно 1 — сервер сообщений

```powershell
cd d:\VectrixSecurity\Frogster\server
$env:FROGSTER_ENV="dev"
$env:FROGSTER_REDIS_URL="redis://localhost:16379/0"
$env:FROGSTER_ADDR="0.0.0.0:18080"
go run ./cmd/frogsterd
```

Ждите строку:

```
msg="http server listening" addr=0.0.0.0:18080
```

### Окно 2 — сервер вложений

```powershell
cd d:\VectrixSecurity\Frogster\server
$env:FROGSTER_ENV="dev"
$env:FROGSTER_REDIS_URL="redis://localhost:16379/0"
$env:FROGSTER_FILED_ADDR="0.0.0.0:18081"
go run ./cmd/filed
```

Ждите:

```
msg="file server listening" addr=0.0.0.0:18081
```

> `0.0.0.0` вместо `localhost` — обязательно. Иначе сервер слушает только сам
> компьютер и телефон до него не достучится.

**Оставьте оба окна открытыми.** В них будут идти логи — они пригодятся.

---

## Часть 5. Открыть порты в брандмауэре

Один раз, **PowerShell от администратора**:

```powershell
New-NetFirewallRule -DisplayName "Frogster" -Direction Inbound -Protocol TCP -LocalPort 18080,18081 -Action Allow
```

Без этого Windows молча заблокирует телефон — самая частая причина
«приложение не видит сервер».

## Часть 6. Проверить связь ДО установки приложения

Это ключевой шаг. **Если он не пройдёт, дальше идти бессмысленно.**

Возьмите телефон, откройте браузер и наберите (подставьте свой адрес):

```
http://ВАШ_IP:18080/healthz
```

Должно появиться:

```json
{"status":"ok"}
```

**Появилось** — сеть в порядке, идём дальше.
**Не появилось** — см. «Если что-то пошло не так», пункт про сеть.

## Часть 7. Собрать и поставить приложение

### На телефон

Включите отладку: **Настройки** → **О телефоне** → 7 раз тапнуть по
**«Номер сборки»** → появится раздел «Для разработчиков» → включить
**Отладку по USB**. Подключите кабелем, разрешите отладку.

Проверьте, что телефон виден:

```powershell
cd d:\VectrixSecurity\Frogster\client
flutter devices
```

Соберите и установите (подставьте свой IP в трёх местах):

```powershell
flutter build apk --debug --dart-define=FROGSTER_SERVER=http://ВАШ_IP:18080 --dart-define=FROGSTER_FILE_HOST=ВАШ_IP --dart-define=FROGSTER_FILE_PORT=18081

flutter install
```

### На компьютер

```powershell
flutter build windows --dart-define=FROGSTER_SERVER=http://ВАШ_IP:18080 --dart-define=FROGSTER_FILE_HOST=ВАШ_IP --dart-define=FROGSTER_FILE_PORT=18081
```

Готовый файл — запускать двойным кликом:

```
d:\VectrixSecurity\Frogster\client\build\windows\x64\runner\Release\frogster.exe
```

> IP нужно указывать **при каждой сборке**: он вшивается в приложение. Если
> адрес компьютера изменился — пересоберите.

## Часть 8. Сценарии проверки

### 8.1. Регистрация

| Где | Что делать |
|---|---|
| Компьютер | Запустить `frogster.exe` → **Create a new account** |
| | Имя: `alice`, пароль: `correct-horse-battery` |
| Телефон | Открыть **Frogster** → **Create a new account** |
| | Имя: `bob`, пароль: `correct-horse-battery` |

**Пароль минимум 10 символов**, иначе форма не пропустит.

В окне 1 (сервер) должно появиться по строке на каждого:

```
msg="user registered" user_id=... device_id=... prekeys=100
msg="client connected" ...
```

**Ожидаемо:** оба попали в список чатов (пустой).

---

### 8.2. Переписка

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Компьютер | **+** внизу справа → ввести `bob` → **Start** | Открылся чат |
| 2 | Компьютер | Написать `привет` → отправить | Сообщение справа, галочка |
| 3 | Телефон | — | Сообщение появилось **слева** |
| 4 | Телефон | Ответить `привет и тебе` | Появилось справа |
| 5 | Компьютер | — | Ответ появился **слева** |

В логе сервера на каждое сообщение:

```
msg="message received" user_id=... bytes=...
msg="message accepted" ... seq=1 recipients=1 per_device_payloads=1
```

**`recipients=1`** — верно, когда у собеседника одно устройство.

---

### 8.3. Вход после выхода

Раньше здесь была ошибка про ключи — проверьте, что починилось.

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Компьютер | Шестерёнка → **Sign out** → подтвердить | Вернулись на экран входа |
| 2 | Компьютер | **Sign in** (не Create!) → `alice` + тот же пароль | **Вход прошёл** |

> Важно: выход **стирает ключи и историю** на этом устройстве — так и задумано.
> После входа переписка будет пустой, но новые сообщения пойдут.

В логе должно быть `POST /v1/login status=200`.

---

### 8.4. Офлайн-очередь

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Телефон | Закрыть Frogster полностью (смахнуть из задач) | — |
| 2 | Компьютер | Отправить 3 сообщения подряд | Все с галочкой |
| 3 | Телефон | Открыть Frogster | **Все 3 пришли, по порядку** |

---

### 8.5. Обрыв связи

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Телефон | Выключить Wi-Fi | Полоса **«Offline — messages will send later»** |
| 2 | Телефон | Включить Wi-Fi | Полоса пропала за несколько секунд |

---

### 8.6. Safety number

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Компьютер | В чате — иконка щита вверху справа | 60 цифр группами |
| 2 | Телефон | То же самое | **Те же самые цифры** |

Совпадение цифр означает, что между вами нет посредника. Не совпали —
что-то не так с ключами.

---

### 8.7. Смена телефона

Самый частый жизненный сценарий: человек купил новый телефон. Аккаунт тот же,
ключи — новые (приватный ключ привязан к устройству и не переносится).

Как сымитировать, не покупая телефон: на телефоне **Настройки → Sign out →
Erase everything**, потом войти тем же логином и паролем. Это ровно то же
самое, что новое устройство.

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Телефон | Erase everything, затем вход тем же логином | Вошло; чаты пустые |
| 2 | Компьютер | Написать в старый чат | **Сообщение уходит**, появляется плашка «safety number changed» |
| 3 | Телефон | Прочитать и ответить | Дошло в обе стороны |
| 4 | Оба | Сверить safety number (щит) | Цифры снова совпадают |

Ключевое: связь **не должна ломаться**. Плашка синяя, информационная — это не
ошибка. Старая переписка на новом устройстве не восстанавливается: её ключи
остались на старом, и это ожидаемо.

Если хотите строгий режим (отправка блокируется до сверки) — он есть в коде,
`TrustPolicy.strict`, см. [docs/crypto-protocol.md](docs/crypto-protocol.md).

---

### 8.8. Отзыв старого устройства

После смены телефона старое устройство стоит отключить, иначе контакты
продолжают шифровать и на него.

| Шаг | Где | Действие | Ожидаемо |
|---|---|---|---|
| 1 | Компьютер | Настройки → Active sessions | Видно старое устройство |
| 2 | Компьютер | Крестик напротив него → подтвердить | Пропало из списка |
| 3 | Телефон | Написать сообщение | Уходит только на актуальные устройства |

Проверить на сервере, что устройство отозвано:

```powershell
docker compose -f deploy/docker-compose.yml exec postgres psql -U frogster -d frogster -c "SELECT device_name, revoked_at FROM devices ORDER BY created_at;"
```

У отозванного должна стоять дата в `revoked_at`, а не `NULL`.

## Часть 9. Проверить, что сервер правда ничего не видит

Это главное в проекте — стоит убедиться лично.

### 9.1. Логи

Посмотрите на окно 1 после отправки сообщений. Вы увидите **только**
идентификаторы и размеры:

```
msg="message received" user_id=1b1a... device_id=4677... bytes=748
```

**Текста сообщений там нет и быть не может.**

### 9.2. База данных

Отправьте сообщение с запоминающимся словом, например `СЕКРЕТНОЕСЛОВО`.
Затем в новом окне PowerShell:

```powershell
cd d:\VectrixSecurity\Frogster
docker compose -f deploy/docker-compose.yml exec postgres psql -U frogster -d frogster -c "SELECT count(*) FROM message_deliveries WHERE position('СЕКРЕТНОЕСЛОВО' in encode(ciphertext,'escape')) > 0;"
```

Ожидаемо:

```
 count
-------
     0
```

Ноль означает, что слова в базе нет — там только шифротекст.

Посмотреть, что лежит на самом деле:

```powershell
docker compose -f deploy/docker-compose.yml exec postgres psql -U frogster -d frogster -c "SELECT substring(encode(ciphertext,'base64') for 60) FROM message_deliveries LIMIT 3;"
```

Будет нечитаемый набор символов.

### 9.3. Вложения на диске

Отправьте фото, затем:

```powershell
dir d:\VectrixSecurity\Frogster\server\data\blobs /s
```

Файлы там зашифрованы: у PNG не будет сигнатуры формата, открыть их нельзя.

## Если что-то пошло не так

### Телефон не открывает `/healthz`

1. **Проверьте с компьютера:** откройте `http://ВАШ_IP:18080/healthz` в браузере
   на ПК. Не работает — сервер не слушает сеть, проверьте `0.0.0.0` в командах.
2. **Брандмауэр** — выполните команду из части 5 от администратора.
3. **Разные сети** — телефон может быть на мобильном интернете или в гостевой
   Wi-Fi сети. Проверьте, что оба на одной сети.
4. **VPN** — выключите на обоих устройствах.

### `429 Too Many Requests` при регистрации

Лимит 5 регистраций в час с одного адреса. Сбросить:

```powershell
cd d:\VectrixSecurity\Frogster
docker compose -f deploy/docker-compose.yml exec redis redis-cli EVAL "local ks=redis.call('keys','frogster:rl:*'); for i=1,#ks do redis.call('del',ks[i]) end; return #ks" 0
```

### Redis не стартует, ошибка про порт

Windows резервирует диапазоны портов под Hyper-V/WSL. Посмотреть:

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
```

Если `16379` попал в занятый диапазон — выберите другой:

```powershell
$env:REDIS_PORT="26379"
docker compose -f deploy/docker-compose.yml up -d
```

И укажите его серверам: `$env:FROGSTER_REDIS_URL="redis://localhost:26379/0"`.

### Сообщения не приходят

1. Посмотрите **окно 1**: есть ли `message accepted`? Нет — сообщение не дошло
   до сервера, проблема в сети.
2. Есть, но не появляется у получателя — соберите логи телефона:

```powershell
cd d:\VectrixSecurity\Frogster\client
flutter logs
```

Ищите строки `[frogster] decrypt failed` — там будет причина.

### Начать всё с чистого листа

Стирает **все** аккаунты и переписку:

```powershell
cd d:\VectrixSecurity\Frogster
docker compose -f deploy/docker-compose.yml exec postgres psql -U frogster -d frogster -c "TRUNCATE message_deliveries, messages, group_sender_key_distributions, chat_members, chats, active_sessions, one_time_pre_keys, signed_pre_keys, devices, users CASCADE;"
```

После этого на обоих устройствах сделайте **Sign out** (или переустановите
приложение) — иначе у них останутся ключи от несуществующих аккаунтов.


## Остановить всё

```powershell
# В окнах серверов: Ctrl+C

cd d:\VectrixSecurity\Frogster
docker compose -f deploy/docker-compose.yml down
```

Данные сохранятся до следующего запуска. Чтобы стереть и их — добавьте `-v`.
