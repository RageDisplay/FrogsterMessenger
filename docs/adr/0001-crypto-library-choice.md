# ADR 0001: Реализация Double Ratchet вместо готовой библиотеки

**Статус**: принято
**Дата**: 2026-07-29

## Контекст

Требования к клиенту: мультиплатформенность (Windows/Linux/Android/iOS/macOS),
бесплатность и **возможность публикации в App Store**.

Проверены все зрелые реализации Signal Protocol для Dart. Лицензии взяты из
файлов LICENSE в репозиториях и поля `license` в pubspec, а не из бейджей
на странице pub.dev:

| Пакет | Лицензия | Источник проверки |
|---|---|---|
| `libsignal_protocol_dart 0.8.2` | **GPL-3.0** | LICENSE, MixinNetwork/libsignal_protocol_dart |
| `libsignal 6.1.1` | **AGPL-3.0** | поле `license` в pubspec |
| `vodozemac 0.5.0` | **AGPL-3.0** | pub.dev |
| `flutter_olm 2.0.0` | **AGPL-3.0** | pub.dev |
| `signalapp/libsignal` (upstream Rust) | **AGPL-3.0** | LICENSE + README |

Важно: страница pub.dev для `libsignal` показывает бейдж «MIT», однако поле
`license` в самом pubspec — `AGPL-3.0`. Доверять следует pubspec и LICENSE.

GPL/AGPL несовместимы с ToS App Store (пункт о запрете дополнительных
ограничений на пользователя) — это документированная причина реальных снятий
приложений. Поскольку Dart линкуется статически, использование такой библиотеки
делает весь клиент производным произведением.

Порт из upstream-референса Signal не решает проблему: он тоже AGPL-3.0.

## Решение

Реализуем X3DH и Double Ratchet самостоятельно поверх permissive-примитивов:

- `cryptography` 2.9.0 (Apache-2.0) — X25519, HKDF-SHA256, AES-256-GCM
- `pointycastle` 4.0.0 (MIT) — дополнительные примитивы

**Криптографические примитивы не изобретаются.** Пишется только протокольный
слой (композиция примитивов) строго по опубликованным спецификациям Signal:
[X3DH](https://signal.org/docs/specifications/x3dh/),
[Double Ratchet](https://signal.org/docs/specifications/doubleratchet/),
[XEdDSA](https://signal.org/docs/specifications/xeddsa/).

Мандат исходного задания («pointycastle или dart:ffi») соблюдается буквально.

## Отвергнутые альтернативы

**dart:ffi к Go-крипте.** Потребовал бы сборки `.dll`/`.so`/`.a` под Windows,
Linux, три Android ABI и iOS плюс обвязку CMake/Gradle/Podspec. Прямой конфликт
с требованием мультиплатформенной сборки без ошибок. Кроме того, граница FFI
сама по себе способна вносить уязвимости (неосвобождённые буферы с ключевым
материалом).

**GPL-библиотека с отказом от iOS.** Отвергнуто: App Store заявлен как
требование.

## Последствия

Это **самая рискованная часть проекта**. Ошибка в ratchet не проявляется как
краш — она тихо ломает forward secrecy, а тесты остаются зелёными.

Обязательные меры (Этап 5):
- изоляция за интерфейсом `CryptoEngine` — реализация заменяема, если
  лицензионные обстоятельства изменятся;
- тестовые векторы из спецификаций Signal;
- тест доставки не по порядку (отправка 1,2,3 → доставка 3,1,2);
- тест уничтожения message key сразу после расшифровки;
- тест переживания рестарта (состояние сессии восстанавливается);
- ограничение `MKSKIPPED` (MAX_SKIP = 1000) — иначе DoS через память;
- перед продакшеном — внешний аудит криптослоя.
