# Развёртывание на сервере

Как поднять Frogster на VPS одной командой и подключить к нему приложения.

Для локального теста «ПК + телефон в одной Wi-Fi» это не нужно, см.
[TESTING.md](TESTING.md).

---

## Что понадобится

- VPS на **Ubuntu 22.04 или 24.04** с белым IP и root-доступом. Хватит 1 ГБ
  RAM: если памяти меньше 2 ГБ, скрипт сам добавит swap для сборки.
- Открытые порты **80 и 443**. Если у провайдера есть свой firewall или
  security group в панели управления, откройте их и там.
- По желанию — **доменное имя** с A-записью на IP сервера. С доменом сертификат
  обычный, и приложению не нужен отпечаток.

Docker, Go и прочее ставить заранее не нужно.

---

## Установка

```bash
git clone https://github.com/RageDisplay/FrogsterMessenger.git
cd FrogsterMessenger
sudo ./deploy/install.sh
```

Скрипт спросит одно: домен или голый IP. Дальше всё делает сам:

1. ставит Docker и нужные пакеты;
2. генерирует пароли и ключи в `deploy/.env` (доступен только root). Они
   создаются один раз и при обновлениях не меняются;
3. настраивает HTTPS через Caddy:
   - **домен**: сертификат Let's Encrypt;
   - **IP**: сначала пробует IP-сертификат Let's Encrypt. Если не вышло,
     включает собственный центр сертификации сервера, и приложение
     закрепляет его по отпечатку;
4. открывает в `ufw` порты SSH, 80 и 443;
5. собирает и запускает сервисы: PostgreSQL, Redis, сервер сообщений, сервер
   вложений и Caddy. Наружу смотрит только Caddy;
6. ставит команду `frogster` и ежедневный бэкап базы.

В конце он печатает всё, что нужно приложению:

```
 Frogster is running

  Server address for the app:  https://203.0.113.5
  Certificate fingerprint:     F857-77EC-67B6-AD12-911B-1BB3-7902-7BC0
```

**Отпечаток** появляется только в режиме собственного центра сертификации.
Его нужно ввести в приложении при первом входе. Посмотреть снова:
`sudo frogster fingerprint`.

### Без вопросов

```bash
sudo ./deploy/install.sh --domain chat.example.com --email you@example.com --yes
sudo ./deploy/install.sh --ip 203.0.113.5 --yes
```

`--help` покажет все параметры: `--self-signed`, `--no-firewall`, `--dir` и
другие.

## Подключить приложение

На экране входа:

1. **Server** — адрес из вывода установщика: домен или IP.
2. Если сервер работает со своим сертификатом, приложение попросит
   **Certificate fingerprint**. Введите отпечаток из вывода установщика.
   Приложение скачает сертификат сервера и сверит его с введённым
   отпечатком. При несовпадении оно откажется подключаться: значит, на пути
   кто-то подменяет соединение.
3. Логин и пароль, «Create account» для нового аккаунта.

Вводится всё один раз: при следующих запусках вход автоматический.

Адрес сервера больше не зашивается в сборку, поэтому один APK подходит для
любого сервера. Можно задать адрес по умолчанию для экрана входа:
`--dart-define=FROGSTER_SERVER=chat.example.com`.

## Управление

```bash
frogster status            # что запущено и живо ли
frogster logs              # логи всех сервисов (logs frogsterd — одного)
sudo frogster restart
sudo frogster update       # обновить сервер, см. ниже
sudo frogster backup       # бэкап базы в /var/backups/frogster
sudo frogster restore FILE # восстановить базу из бэкапа (текущие данные удаляются)
sudo frogster fingerprint  # отпечаток сертификата для приложения
sudo frogster reset        # удалить ВСЁ: аккаунты, сообщения, вложения
```

Бэкап базы делается каждую ночь в 03:17, хранятся последние 7. Вложения в
бэкап не входят: они живут 30 дней и без ключей из переписки бесполезны.

После `frogster reset` сервер получает новый сертификат. Приложениям нужно
выйти и войти заново с новым отпечатком.

### Обновление

Запушьте изменения на GitHub, потом со своего Windows-компьютера (из корня
репозитория):

```powershell
.\deploy\update-server.ps1 root@IP_СЕРВЕРА
```

или прямо на сервере: `sudo frogster update`. Что происходит:

1. Если на GitHub ничего нового — так и пишет и ничего не трогает
   (`--force` / `-Force` пересоберёт всё равно).
2. Показывает, какие коммиты приедут.
3. Делает бэкап базы.
4. Берёт код ровно как на GitHub — в том числе после force-push или
   пересоздания репозитория.
5. Пересобирает и перезапускает, миграции базы применяются сами, ждёт, пока
   сервисы ответят «здоров».
6. Если новая версия не поднялась — сам возвращает предыдущую и подсказывает
   команду восстановления базы из только что сделанного бэкапа.

Данные, ключи и сертификат при обновлении не меняются, приложениям ничего
делать не нужно. Локальные правки в `/opt/frogster` обновление не затирает,
а отказывается работать, пока их не уберут.

## Что внутри

| Сервис | Назначение | Снаружи |
|---|---|---|
| caddy | HTTPS, раздаёт трафик по сервисам | 80, 443 |
| frogsterd | REST API и WebSocket | нет |
| filed | вложения по gRPC | нет, через Caddy на 443 |
| postgres | база | нет |
| redis | rate limiting, присутствие | нет |

Файлы:

- `deploy/docker-compose.prod.yml` — состав сервисов;
- `deploy/Caddyfile.tmpl` — шаблон конфигурации Caddy; рабочий `deploy/Caddyfile`
  рендерит установщик;
- `deploy/.env` — секреты, генерирует установщик. В git не попадает;
- `deploy/install.sh`, `deploy/frogster.sh` — установщик и команда управления.

Сервер сам удаляет то, что больше не нужно:

- недоставленные сообщения через 30 дней;
- доставленные копии через 7 дней;
- истёкшие сессии и использованные ключи;
- вложения старше 30 дней.

## Если что-то пошло не так

**Let's Encrypt не выдаёт сертификат для домена.** Проверьте, что A-запись
указывает на сервер (`dig +short ваш.домен`) и что порты 80/443 открыты и в
`ufw`, и у провайдера. Caddy продолжает попытки сам; смотреть:
`frogster logs caddy`.

**Приложение: «The certificate fingerprint does not match».** Сверьте с
`sudo frogster fingerprint`. Если совпадает, а ошибка остаётся, соединение
кто-то перехватывает.

**Приложение: «Could not reach the server».** Сначала с компьютера:
`curl -k https://АДРЕС/healthz` должен вернуть `{"status":"ok"}`. Нет ответа —
это firewall или security group. `Connection refused` — сервисы не запущены,
`frogster status`.

**Сборка падает с `signal: killed`.** Не хватило памяти. Установщик добавляет
swap, если RAM меньше 2 ГБ. Если swap не включился, его можно добавить
вручную и запустить установку снова.
